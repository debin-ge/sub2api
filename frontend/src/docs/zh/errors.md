# 错误排查

Sub2API 错误可能来自网关本身，也可能来自上游平台。排查时先确认 Base URL、API Key、端点路径、模型名和当前分组权限，再判断是否需要联系管理员。

## 排查顺序

建议按下面顺序定位问题：

1. 用当前环境变量调用 `/v1/models`，确认密钥和基础网络正常。
2. 用同一个模型发起非流式最小请求。
3. 如果非流式成功，再验证流式请求或业务请求。
4. 对比本地、测试、生产的 Base URL、API Key、模型名和代理配置。
5. 根据状态码判断是认证、权限、路径、限流还是上游问题。

最小验证命令：

```bash
curl -i "${BASE_URL}v1/models" \
  -H "Authorization: Bearer $YOUR_KEY"
```

## HTTP 状态码

| 状态码 | 含义 | 常见原因 | 建议处理 |
| --- | --- | --- | --- |
| 401 | 未认证 | API Key 缺失、格式错误、密钥无效或请求头未使用 Bearer。 | 检查 `Authorization: Bearer $YOUR_KEY`，确认密钥未过期或被删除。 |
| 403 | 无权限 | 密钥有效，但分组不允许访问该模型、渠道或端点。 | 查询 `/v1/models`，联系管理员检查分组、价格和模型权限。 |
| 404 | 未找到 | 路径不存在、端点未启用、模型名错误或映射缺失。 | 核对接口族和路径，确认模型名来自当前部署返回结果。 |
| 429 | 请求过多 | 命中 Sub2API、上游账号、分组或客户端侧速率限制。 | 降低并发，增加重试退避，或联系管理员调整限流和额度。 |
| 5xx | 服务错误 | 上游故障、网络异常、渠道配置错误、服务内部错误。 | 稍后重试，记录错误信息和请求时间，必要时切换模型或联系管理员。 |

## 401 未认证

优先检查 API Key 是否真的发送到请求中：

```bash
echo "$YOUR_KEY" | wc -c
curl -i "${BASE_URL}v1/models" \
  -H "Authorization: Bearer $YOUR_KEY"
```

常见原因：

| 原因 | 处理 |
| --- | --- |
| 环境变量未设置 | 重新执行 `export YOUR_KEY="..."`。 |
| 请求头缺少 Bearer | 使用 `Authorization: Bearer $YOUR_KEY`。 |
| 密钥被删除或禁用 | 登录控制台或联系管理员确认。 |
| 使用了错误环境的密钥 | 区分测试、预发和生产 API Key。 |

401 通常不应自动重试。先修复认证配置。

## 403 无权限

403 表示密钥可能有效，但当前分组没有访问权限。常见检查项：

1. `/v1/models` 是否返回目标模型。
2. 当前用户或 API Key 是否绑定正确分组。
3. 分组是否启用目标端点和渠道。
4. 额度、余额或有效期是否满足请求。
5. 管理员是否近期调整过权限或价格。

403 不等于 Base URL 错误，也不一定是密钥拼写错误。重点查权限和分组策略。

## 404 未找到

404 常见于路径、端点或模型名不匹配：

| 检查项 | 示例 |
| --- | --- |
| 是否重复 `/v1` | `https://tiktoken.net/v1/v1/chat/completions` 是错误路径。 |
| 是否缺少 `/v1beta` | Gemini 原生请求需要 `/v1beta/models/...`。 |
| 是否缺少 `/antigravity` | Antigravity 客户端需要对应路径。 |
| 模型名是否存在 | 使用 `/v1/models` 或 `/v1beta/models` 返回结果。 |
| 端点是否启用 | 有些部署可能未开放图片、embedding 或 Responses。 |

## 模型不可用

常见提示包括模型不存在、模型未启用、无可用渠道或上游拒绝请求。可能原因：

| 原因 | 说明 |
| --- | --- |
| 分组未开放 | 当前 API Key 所属分组没有该模型权限。 |
| 模型映射缺失 | 请求模型名没有映射到可用上游模型。 |
| 渠道不可用 | 上游账号额度不足、密钥失效、被限流或被禁用。 |
| 价格配置不匹配 | 管理员未为该模型配置价格或倍率，导致请求被拒绝。 |
| 接口族错误 | 使用 Anthropic 模型调用 OpenAI 请求体，或使用 Gemini 模型调用错误端点。 |

处理建议：先调用 `${BASE_URL}v1/models`，使用返回列表中的模型名重试；仍失败时让管理员检查分组、渠道和模型映射。

## 不支持的端点

如果返回 404 或明确提示 unsupported endpoint，通常说明当前部署没有启用该路径，或客户端把 Base URL 拼接错了。

| 检查项 | 示例 |
| --- | --- |
| OpenAI SDK | `baseURL` 通常应为 `https://tiktoken.net/v1`。 |
| Anthropic 兼容 | 通常请求 `${BASE_URL}v1/messages`，不要误拼成重复 `/v1/v1/messages`。 |
| Gemini 原生 | 使用 `${BASE_URL}v1beta/models/{model}:generateContent`。 |
| Antigravity | 使用 `${BASE_URL}antigravity/...`，并确认管理员已启用。 |

## 未分组或密钥未绑定

如果 API Key 没有关联有效分组，可能出现无模型、403、计费失败或请求被拒绝。请联系管理员确认：

1. API Key 是否存在且启用。
2. 用户是否绑定了有效分组。
3. 分组是否配置了模型、渠道和价格。
4. 分组额度、余额或过期时间是否满足请求。

## 429 限流

429 表示请求过快或超过额度。处理建议：

| 场景 | 建议 |
| --- | --- |
| 单用户高频请求 | 降低并发，增加客户端节流。 |
| 批处理任务 | 分批执行，限制每批大小和间隔。 |
| 自动重试过多 | 使用指数退避，并设置最大重试次数。 |
| 上游账号限流 | 联系管理员确认渠道状态或切换备用渠道。 |
| 分组额度不足 | 查看用量或联系管理员调整额度。 |

不要在 429 后立即无限重试，否则会放大限流和费用。

## 流式中断

流式请求可能在生成中断开，表现为 SSE 连接关闭、客户端超时或输出不完整。

| 可能原因 | 建议 |
| --- | --- |
| 客户端超时过短 | 增加 HTTP client、代理和负载均衡超时时间。 |
| 代理缓冲 | 关闭反向代理缓冲，确保 SSE 分块及时转发。 |
| 上游限流或错误 | 降低并发，检查上游账号状态和错误日志。 |
| 网络不稳定 | 增加重试策略，但避免对非幂等请求盲目重放。 |
| 模型输出过长 | 控制 `max_tokens` 或拆分任务。 |

如果同一模型的非流式请求正常，但流式请求持续失败，优先检查代理、SSE 支持和客户端解析逻辑。

## 最小复现模板

向管理员或支持人员反馈问题时，建议提供下面信息，不要提供完整 API Key：

```text
时间范围：
请求路径：
模型名：
状态码：
错误摘要：
API Key 标识：仅提供名称或后几位
客户端类型：curl / OpenAI SDK / Claude Code / Gemini / 其他
是否流式：
本地或生产环境：
```

可复现的最小 curl：

```bash
curl -i "${BASE_URL}v1/chat/completions" \
  -H "Authorization: Bearer $YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      { "role": "user", "content": "ping" }
    ],
    "max_tokens": 20
  }'
```

如果最小请求成功，但业务请求失败，说明问题更可能来自业务参数、上下文长度、流式处理、工具调用或客户端超时。
