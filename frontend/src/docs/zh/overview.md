# 产品概览

{{SITE_NAME}} 是一个面向多模型服务的统一 API 网关。它把不同上游平台的模型、鉴权、额度、分组和计费配置收敛到同一套入口，方便应用侧用稳定的 Base URL 和 API Key 接入。

实际可用能力取决于当前部署的管理配置，包括用户所在分组、上游账号状态、模型映射、渠道价格、额度策略和管理员启用的端点。不要假设每个 {{SITE_NAME}} 部署都支持全部模型或全部接口。

## 适用场景

| 场景 | 说明 |
| --- | --- |
| 多模型统一接入 | 应用只维护一个 Base URL，通过模型名或映射访问不同上游。 |
| 团队密钥管理 | 为不同用户、项目或分组分配独立 API Key，并控制可用模型与额度。 |
| 兼容现有客户端 | 复用 OpenAI、Anthropic、Gemini、Codex、Claude Code 等客户端的常见接入方式。 |
| 用量与成本治理 | 结合渠道价格、分组策略和后台统计管理请求成本。 |
| 渐进迁移 | 在不大改业务代码的情况下切换上游账号、模型映射或渠道优先级。 |

## 核心概念

| 概念 | 说明 |
| --- | --- |
| Base URL | 当前 {{SITE_NAME}} 部署的访问地址，例如 `{{BASE_URL}}`。 |
| API Key | 由 {{SITE_NAME}} 分发的访问密钥，通常以 `Bearer` Token 形式传入。 |
| 分组 | 管理员用来控制用户可访问模型、渠道、价格和额度的配置单元。 |
| 渠道 | {{SITE_NAME}} 连接到上游平台或账号的配置。不同渠道可支持不同模型和接口。 |
| 模型映射 | 管理员可以把用户请求中的模型名映射到实际上游模型。 |
| 端点兼容层 | {{SITE_NAME}} 提供 OpenAI、Anthropic、Gemini、Antigravity 等风格的接口入口。 |

## 基本调用流程

1. 从管理员或控制台获取 Base URL 和 API Key。
2. 设置环境变量：

```bash
export BASE_URL="{{BASE_URL}}"
export YOUR_KEY="your-api-key"
```

3. 调用 `/v1/models` 查看当前密钥实际可用的模型列表。
4. 按客户端或接口选择请求格式，例如 `/v1/chat/completions`、`/v1/messages`、`/v1/responses` 或 Gemini 原生端点。
5. 根据响应、错误码和用量信息调整模型、分组或上游配置。

## 推荐接入顺序

| 步骤 | 建议 |
| --- | --- |
| 验证密钥 | 先调用 `${BASE_URL}v1/models`，确认鉴权与模型列表正常。 |
| 选择接口 | OpenAI SDK 优先使用 `/v1/chat/completions` 或 `/v1/responses`；Claude 类客户端优先使用 `/v1/messages`；Gemini 原生客户端使用 `/v1beta` 路径。 |
| 固定模型名 | 使用 `/v1/models` 返回的模型名，或管理员明确提供的映射名。 |
| 开启流式 | 确认客户端支持流式响应后，再使用 `stream: true` 或 SSE 端点。 |
| 排查失败 | 遇到 401、403、404、429 或上游 5xx 时，先确认密钥、分组、端点和模型是否匹配当前部署。 |
