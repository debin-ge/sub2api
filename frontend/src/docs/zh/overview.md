# 产品概览

{{SITE_NAME}} 是一个面向多模型服务的统一 API 网关。它把不同上游平台的模型、鉴权、额度、分组和计费配置收敛到同一套入口，方便应用侧以稳定的 Base URL 和 API Key 进行接入。

> [!IMPORTANT]
> **注意**：实际可用能力取决于当前部署的管理配置，包括用户所属的分组、上游账号状态、模型映射关系、渠道价格、额度策略以及管理员启用的端点。**请勿假定每个 {{SITE_NAME}} 部署都支持全部模型或全部接口。**

---

## 适用场景

| 场景 | 说明 |
| :--- | :--- |
| **多模型统一接入** | 客户端应用只需维护一个 Base URL，便能通过不同的模型名称或映射直接访问各大不同上游服务。 |
| **团队密钥管理** | 为不同的项目、团队成员或分组分发独立的 API Key，精细化限制可使用的模型列表与额度上限。 |
| **兼容现有客户端** | 完美复用 OpenAI、Anthropic、Gemini、Codex、Claude Code 等第三方客户端工具的常规接入方法。 |
| **用量与成本治理** | 结合渠道价格乘数、分组限额策略以及后台详细统计，智能化管控请求调用成本。 |
| **渐进式平滑迁移** | 在不大改业务代码的前提下，在后台灵活切换上游账号渠道、调整模型映射或修改优先级权重。 |

## 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **Base URL** | 当前 {{SITE_NAME}} 部署节点的网络访问地址，例如 `{{BASE_URL}}`。 |
| **API Key** | 由 {{SITE_NAME}} 平台分发的访问凭证密钥，通常通过 `Bearer` Token 形式在 HTTP 请求头中传入。 |
| **分组 (Group)** | 管理员用来控制用户能调用的模型集合、渠道优先级、计费价格和额度的核心配置单元。 |
| **渠道 (Channel)** | {{SITE_NAME}} 对接各上游平台或 API 供应商账号的物理配置。不同渠道所支持的模型与端点有所不同。 |
| **模型映射 (Mapping)** | 管理员可以通过规则把请求里的某个公开模型名称（如 `gpt-4`）透明地重定向到特定的实际上游模型。 |
| **端点兼容层 (Compat)** | 网关提供的 API 路由兼容层，支持 OpenAI、Anthropic、Gemini、Antigravity 等多种主流调用风格。 |

## 基本调用流程

1. 从管理员或控制台获取平台的 **Base URL** 和 **API Key**。
2. 设置本地环境变量：
   ```bash
   export BASE_URL="{{BASE_URL}}"
   export YOUR_KEY="your-api-key"
   ```
3. 查询 `/v1/models` 端点，确认您的 API 密钥有效，并获取当前分组可访问的模型列表。
4. 根据您的客户端或业务逻辑选择适合的请求格式，例如调用 `/v1/chat/completions`、`/v1/messages`、`/v1/responses` 或 Gemini 原生接口。
5. 针对系统返回的响应结果、错误状态码或用量监控，动态调整您的请求逻辑。

## 推荐接入顺序

| 步骤 | 建议操作 |
| :--- | :--- |
| **1. 验证密钥** | 首先请求 `${BASE_URL}v1/models`，确认 HTTP 状态码为 200，且模型列表返回正常。 |
| **2. 选择接口** | 使用 OpenAI SDK 时，优先接入 `/v1/chat/completions` 或 `/v1/responses`；Claude 类客户端接入 `/v1/messages`；Gemini 原生客户端则访问 `/v1beta` 路径。 |
| **3. 绑定模型名** | 始终使用前文 `/v1/models` 实际返回的模型名，或者管理员明确提供的模型映射别名。 |
| **4. 开启流式响应** | 在确认您的业务客户端已正确实现 SSE 流式处理后，在请求体中启用 `stream: true` 以获得极速首字体验。 |
| **5. 错误排查** | 当遭遇 401、403、404、429 或上游 5xx 时，可参照平台的“错误排查”手册定位是密钥、分组还是端点路径问题。 |
