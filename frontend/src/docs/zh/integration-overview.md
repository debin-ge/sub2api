# 接入总览

本页帮助你从零开始完成接入准备，并在 4 种接入方式中选到最适合你的一种。即使你从未使用过 API、从未打开过终端，按照下面的步骤逐步操作也能完成。

## 接入前提

在使用任何客户端、CLI 或代码接入之前，请先完成下面 3 步。**后面所有接入页都默认你已完成这里的准备。**

### 第 1 步：拿到 Base URL 和 API Key

**Base URL** 是 {{SITE_NAME}} 的服务地址。它就是你现在浏览器地址栏中本站的地址：

```text
{{BASE_URL}}
```

**API Key** 是调用服务的凭证（一串以 `sk-` 开头的字符）。获取方式：

1. 登录 {{SITE_NAME}}（就是本站）。
2. 点击左侧菜单中的 **「API 密钥」**（API Keys）。
3. 点击 **「创建密钥」** 按钮，填写名称（随便起，例如"我的第一个密钥"），确认创建。
4. 创建成功后**立即复制**并保存到安全的地方（例如密码管理器）。出于安全考虑，完整密钥通常只显示一次。

> 密钥相关的权限、分组和安全说明，详见 [API Key 与账户](/docs/api-keys)。

### 第 2 步：打开终端并验证密钥

「终端」是输入文字命令的窗口。打开方式：

- **macOS**：按 `Command + 空格` 打开聚焦搜索，输入 `终端` 或 `Terminal`，按回车。
- **Windows**：点击开始菜单，输入 `PowerShell`，按回车。

打开后，先把密钥存进环境变量 `API_KEY`（引号里换成第 1 步复制的真实密钥），按回车执行：

```bash
export API_KEY="在这里粘贴你的API密钥"
```

> Windows PowerShell 的等价写法：`$env:API_KEY="在这里粘贴你的API密钥"`。

然后**整段复制**下面的命令执行（`${API_KEY}` 会自动读取刚才设置的值，不用改）：

```bash
curl "{{BASE_URL}}v1/models" \
  -H "Authorization: Bearer ${API_KEY}"
```

**预期结果**：终端会输出一段 JSON 文本，里面有 `"data": [...]`，其中每一项的 `"id"` 就是一个你可以使用的模型名，例如：

```json
{
  "object": "list",
  "data": [
    { "id": "claude-sonnet-4-5", "object": "model" },
    { "id": "gpt-5.5", "object": "model" }
  ]
}
```

**如果没有看到模型列表**：

- 输出包含 `401`：密钥没有生效。检查是否完整复制了密钥、`Bearer` 和密钥之间是否有一个空格。
- 输出包含 `404` 或无法连接：Base URL 不对。检查地址是否和浏览器地址栏一致、有没有多打或少打字符。
- 其他错误：见 [错误排查](/docs/errors)。

> **这一步没通过，请不要继续配置任何客户端。** 后续所有接入方式都依赖这两个信息正确。

### 第 3 步：确认你要用的模型

上一步返回的 `"id"` 列表就是你当前可用的模型名。后面配置客户端或写代码时，**模型名必须从这个列表里选**，不要凭记忆填写。

> 模型可用性与分组、渠道有关，详见 [模型与平台](/docs/models)。

## 选择你的接入方式

| 你的场景 | 推荐路径 | 前往 |
| --- | --- | --- |
| 自己写代码调用 API（Python / TypeScript / Go / curl） | 代码接入 | [代码接入](/docs/integration-code) |
| 使用带界面的 IDE 或编辑器（Cursor、VS Code 插件、Trae 等） | 客户端接入 | [客户端接入](/docs/integration-clients) |
| 使用命令行 AI 工具（Codex CLI、Claude Code） | CLI 接入 | [CLI 接入](/docs/integration-cli) |
| 使用账号切换/管理工具（CC-Switch、Cockpit Tools） | 第三方工具 | [第三方工具接入](/docs/integration-tools) |

不确定选哪个？问自己一个问题：**你平时在哪里用 AI 写代码？**

- 在 Cursor / VS Code 这类编辑器里 → 客户端接入。
- 在终端黑窗口里敲 `claude` 或 `codex` → CLI 接入。
- 你在开发自己的应用或脚本 → 代码接入。
- 你有多个中转站账号想统一管理 → 第三方工具。

## 通用配置约定

后续所有接入页遵循同一套写法约定：

| 约定 | 说明 |
| --- | --- |
| `{{BASE_URL}}` | 你的部署地址（本页第 1 步确认的那个）。示例中已自动替换为本站地址。 |
| `${API_KEY}` | 统一的密钥写法。**终端命令**中它会自动读取你 `export API_KEY=...` 设置的值；**配置文件和图形界面**不会自动读取，请替换为真实密钥。 |
| Base URL 结尾 | 不同客户端要求不同：有的要根地址 `{{BASE_URL}}`，有的要 `{{BASE_URL}}v1`。每个接入页会明确写出该用哪个，请严格照抄。 |
| 环境变量 | 形如 `export 名字="值"` 的命令，作用是把配置告诉当前终端窗口。**关掉窗口就失效**；想永久生效需写入配置文件（各接入页会说明）。 |
| 模型名 | 一律以第 3 步查到的列表为准。 |

## 常见接入错误速查

| 现象 | 最常见原因 | 快速处理 |
| --- | --- | --- |
| 401 Unauthorized | 密钥没传上、复制不完整、变量名写错 | 重新复制密钥；检查请求头是 `Authorization: Bearer sk-...` |
| 403 Forbidden | 密钥所在分组没有该模型/端点权限 | 换用 `/v1/models` 里存在的模型；或联系管理员 |
| 404 Not Found | Base URL 多拼或少拼了 `/v1`，或端点未启用 | 对照接入页给出的准确地址逐字符核对 |
| 一直转圈无输出 | 客户端或网络不支持流式（SSE），或超时太短 | 先用本页第 2 步的 curl 验证网络通 |

详细排查见 [错误排查](/docs/errors)。
