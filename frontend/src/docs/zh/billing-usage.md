# 计费与用量

{{SITE_NAME}} 的计费和用量展示取决于当前部署的分组、渠道价格、倍率、额度和管理员策略。不同部署可能采用不同规则，因此本页只说明用户接入时应理解和检查的通用原则。

## 计费总览

{{SITE_NAME}} 按实际用量扣费，不同模型使用不同的计价方式。[模型广场](/plaza) 中每张模型卡片左上角会标注计费类型，展示的价格已经按分组倍率折算。

| 计费类型 | 计价方式 | 单位 |
| --- | --- | --- |
| 文本 | 输入、输出、缓存写入、缓存读取分别计价 | 每 100 万 tokens |
| 图片 | 优先按图片 token 计价；没有 token 用量时按 1K / 2K / 4K 尺寸按张计价 | 每 100 万 tokens / 每张 |
| 视频 | 按分辨率档位（480p / 720p / 1080p）的每秒单价 × 视频时长 | 每秒 |
| 按次 | 每次成功请求固定扣费，与 token 数无关 | 每次 |

## 文本模型

```text
费用 = (输入 tokens × 输入价 + 输出 tokens × 输出价
       + 缓存写入 tokens × 缓存写入价 + 缓存读取 tokens × 缓存读取价) ÷ 1,000,000 × 分组倍率
```

- 输入包括系统提示、历史消息、用户输入、工具定义等；输出包括模型生成的文本、工具调用参数或结构化输出。
- 部分模型按上下文长度分档（例如超过某个 token 数后使用长上下文价），模型详情的「分层定价」会列出每一档。
- DeepSeek 等模型有官方分时价，高峰与空闲时段单价不同，模型详情中会单独说明。
- 流式输出只改变返回方式，不代表免费或更便宜，已经生成的内容仍会计入用量。

## 图片模型

图片模型可能同时配置两种单价，扣费时按以下顺序选择：

1. **按图片 token 计价（优先）**：上游返回图片 token 用量时，按文本输入、图像输入、图像输出的 token 单价计费。
2. **按张计价（兜底）**：上游没有返回图片 token 用量时，按输出图片尺寸对应的档位计费，费用 = 该档位单张价格 × 张数。

尺寸档位按图片长边判断，优先使用上游实际返回的输出尺寸，其次使用请求中的 `size` 参数：

| 尺寸档位 | 判定规则 | 示例 |
| --- | --- | --- |
| 1K | 长边 ≤ 1024px | `1024x1024` |
| 2K | 1024px < 长边 ≤ 2048px | `1536x1024`、`2048x2048` |
| 4K | 2048px < 长边 ≤ 4096px | `3840x2160`、`4096x4096` |

未指定尺寸或 `size` 为 `auto` 时按 2K 计价；长边超过 4096px 的尺寸没有对应价格，请求会被拒绝。

## 视频模型

```text
费用 = 分辨率档位每秒单价 × 视频时长（秒）× 生成数量 × 分组倍率
```

例如某视频模型 720p 单价为每秒 $0.10，生成一段 6 秒的 720p 视频，原价为 $0.60，再按你所在分组的倍率折算成最终扣费。

视频是异步任务，结算规则如下：

| 任务结果 | 扣费 |
| --- | --- |
| 提交成功 | 按预估金额冻结余额 |
| 生成完成 | 按实际时长和分辨率结算；上游未返回用量时按冻结金额结算 |
| 生成失败、取消或过期 | 解冻全部金额，不扣费 |

## 按次计费

部分模型按每次成功请求固定收费，费用与输入输出长度无关。卡片会显示「每次调用」的价格。

## 倍率与 VIP

| 项目 | 说明 |
| --- | --- |
| 分组倍率 | 不同分组倍率不同，模型广场展示的价格已按倍率折算。 |
| 高峰倍率 | 部分分组在高峰时段对 token 计费叠加更高倍率，模型卡片会有高峰标识。 |
| 图片独立倍率 | 部分分组对按张计价的图片使用独立倍率，模型详情「可用分组」中会单独标出。 |
| 视频独立倍率 | 部分分组对视频按秒计价使用独立倍率，同样在「可用分组」中标出。 |
| VIP 价 | VIP 分组的专属价格与普通分组分开展示，互不覆盖。 |

## 影响价格的其他因素

| 因素 | 影响 |
| --- | --- |
| 渠道 | 同一模型可能通过不同上游渠道转发，价格和可用性不同。 |
| 模型映射 | 用户请求的模型名可能被映射到另一个上游模型。 |
| 请求参数 | `max_tokens`、图片尺寸、视频时长与分辨率、批量输入和工具调用都会影响用量。 |
| 重试请求 | 客户端自动重试会产生多次请求和多次计费。 |

如果你需要对账，请以当前部署控制台或管理员提供的账单规则为准。

## 请求前估算成本

在无法精确预估时，可以用以下方式降低不确定性：

1. 先选择适合任务的模型，不要默认使用最高规格模型。
2. 控制上下文长度，只传必要历史消息。
3. 设置合理的 `max_tokens` 或输出上限。
4. 对长文档先摘要或分段处理。
5. 用小流量测试请求观察实际用量。

Anthropic 兼容端点如果支持 token 估算，可以尝试：

```bash
curl "{{BASE_URL}}v1/messages/count_tokens" \
  -H "Authorization: Bearer ${API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-3-5-sonnet-latest",
    "messages": [
      { "role": "user", "content": "请估算这段请求的 token。" }
    ]
  }'
```

该端点是否可用取决于上游和管理员配置。OpenAI、Gemini 或其他接口族请以当前部署支持的能力为准。

## 控制成本的实践

| 做法 | 说明 |
| --- | --- |
| 用 `/v1/models` 确认模型 | 避免请求到错误模型或未授权模型。 |
| 选择合适模型层级 | 简单分类、改写、抽取任务优先使用成本更低的模型。 |
| 限制输出长度 | 设置 `max_tokens`，避免无界生成。 |
| 减少重复上下文 | 不要每次都发送完整历史或无关资料。 |
| 谨慎自动重试 | 对 429、5xx 使用指数退避，并限制最大重试次数。 |
| 监控异常峰值 | 请求量突然升高时及时检查循环调用、批处理或泄露风险。 |

## 查看用量

如果当前部署提供控制台用量页面，你可以查看请求量、模型、时间范围、消费或余额等信息。不同部署展示字段可能不同，常见字段包括：

| 字段 | 含义 |
| --- | --- |
| 时间 | 请求发生时间或统计时间窗口。 |
| 模型 | 用户请求模型名或映射后的模型名。 |
| 输入/输出 | 请求输入和模型输出的 token，或图片张数、视频秒数等计量单位。 |
| 状态 | 成功、失败、上游错误或被限流。 |
| 费用 | 按分组和渠道价格计算后的消费。 |

如果控制台没有用量入口，请向管理员确认查看方式。

## 对账与异常排查

发现用量异常时，先收集以下信息，不要发送完整 API Key：

1. 请求时间范围。
2. API Key 名称或后几位标识。
3. 请求路径和模型名。
4. 客户端或服务名称。
5. 错误码、重试次数和并发量。
6. 是否近期调整了模型、提示词、批处理或定时任务。

常见异常包括：自动重试过多、循环任务未停止、长上下文请求、测试脚本并发过高、密钥泄露或模型映射变更。

## 预算建议

生产接入前建议设置：

| 项目 | 建议 |
| --- | --- |
| 环境隔离 | 测试、预发、生产使用不同 API Key。 |
| 额度上限 | 为高风险项目设置额度或速率限制。 |
| 告警阈值 | 当请求量、费用或失败率异常时通知负责人。 |
| 模型白名单 | 只开放业务需要的模型，减少误用。 |
| 发布观察 | 新版本上线后观察 30 到 60 分钟的请求量和错误率。 |
