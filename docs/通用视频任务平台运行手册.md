# 原生视频首发运行手册

> 更新：2026-09-06。仅适用于本次基础原生视频首发。旧批次操作已移到 `docs/history/通用视频任务平台运行手册-历史.md`，不得混用。生产尚未应用本次迁移，本文件不构成生产操作或真实收费调用授权。

## 1. 功能边界

开放范围：OpenAI API Key、标准余额计费、创建、编辑、延长、角色创建/查询/删除与复用、列表、查询、下载、删除，以及可选客户端回调和上游 webhook。具体账户、模型、秒数、分辨率、价格及 Provider 能力仍必须经发布负责人核对。项目原有 Grok 不迁入此平台。

客户端回调默认关闭；只有 `gateway.video.callback.enabled=true` 且配置非空签名密钥时才接收 `callback_url` 并启动投递 Worker。上游 webhook 只接受已配置账户密钥的签名事件。未开启客户端回调时返回 HTTP 403 / `video_callbacks_disabled`，不应退化为通用 400。

## 2. 配置核对表

| 项目 | 首发要求 | 不满足时 |
|---|---|---|
| `gateway.video.enabled` | 默认 false；仅在批准的隔离或发布环境开启 | API 不开放 |
| `gateway.video.creation_enabled` | 默认 false；创建单独放流 | 不接受新创建；保留既有基础任务的幂等重放与恢复 |
| `gateway.video.callback.enabled` | 默认 false；需要客户端回调时显式开启并配置 `GATEWAY_VIDEO_CALLBACK_SIGNING_SECRET` | 保持关闭；带 `callback_url` 的创建返回 403 |
| `gateway.video.content_proxy.enabled` | true；确认下载并发与超时上限 | 不发布需要下载的首发闭环 |
| `gateway.video.disclosure_policy` | 首发优先 `none`，按需只开放已验收的 `identity` | 不开放长期凭据披露 |
| `totp.encryption_key` / `TOTP_ENCRYPTION_KEY` | 受控部署密钥，重启保持一致；用于持久化回调地址、上游视频 URL 和任务访问凭据的密文；不得写入代码或报告 | 不启用需要持久化密文的视频链路 |
| spool 目录 | 可写、受限权限、容量足够；孤儿清理可运行 | 暂停新建，先恢复磁盘和清理 |
| 上游账户 | 已确认的视频权限、分组绑定、身份与凭据；不使用真实 Key 做无授权探测 | 不开始真实 smoke |
| 模型与价格 | 模型映射、时长/尺寸、计价单位和预估冻结额一致 | 拒绝创建，不临时添加兜底价格 |
| 测试用户 | 标准余额、独立测试 Key、已确认额度和费用上限 | 不发收费请求 |
| Worker | 轮询/资金结算/删除恢复运行，数据库可达 | 不开放创建 |
| 监控 | 已加载视频告警，阈值/接收人/处置负责人明确 | 不放流 |

### 2.1 环境变量部署最小集

视频配置中的 Worker、spool 限额、轮询间隔和下载代理超时都有安全默认值，首次部署不要求逐项填写。需要运维显式提供或决定的环境变量如下：

| 环境变量 | 要求 | 说明 |
|---|---|---|
| `GATEWAY_VIDEO_ENABLED` | 启用视频 API 时必填为 `true` | 总开关；默认 `false` |
| `GATEWAY_VIDEO_CREATION_ENABLED` | 接受新任务时必填为 `true` | 建议上线初期保持 `false`，完成账户、价格和监控核对后再放流 |
| `TOTP_ENCRYPTION_KEY` | 生产必填并保持稳定 | 用于持久化回调地址、上游视频 URL 和任务访问凭据的密文；不得在重启时变化 |
| `GATEWAY_VIDEO_CALLBACK_ENABLED` | 仅需回调时设置为 `true` | 默认 `false`，不影响查询、轮询和下载闭环 |
| `GATEWAY_VIDEO_CALLBACK_SIGNING_SECRET` | 回调开启时条件必填 | 非空随机密钥；缺失时配置校验拒绝启动 |

建议显式保留 `GATEWAY_VIDEO_SPOOL_DIRECTORY`、`GATEWAY_VIDEO_CONTENT_PROXY_ENABLED`、`GATEWAY_VIDEO_DISCLOSURE_POLICY` 和 `GATEWAY_VIDEO_POLL_INTERVAL_SECONDS`，以便部署平台直接展示关键运行策略。其余字段只有在容量测试给出依据后才调优。

仓库 Compose 文件会将上述 `GATEWAY_VIDEO_*` 变量从 `.env` 传入应用容器。自行编写 Kubernetes、Nomad 或云平台部署清单时也必须注入到应用容器；只把值写在部署工具的插值文件中并不等于进程能够读取。视频账户凭据、模型映射、分组绑定和视频价格属于数据库业务配置，不能用这些运行环境变量替代。

### 2.2 API 与兼容参数

- 编辑：`POST /v1/videos/edits`。JSON 使用 `video.id`；上传视频使用 multipart `video`，且必须显式提供 `model`。
- 延长：`POST /v1/videos/extensions`。只接受已完成源视频、`prompt` 与 4/8/12/16/20 秒；最多延长 6 次，拼接总时长不超过 120 秒；不接受角色或图片参考。
- 角色：multipart `POST /v1/videos/characters` 创建；`GET/DELETE /v1/videos/characters/{character_id}` 查询和删除；创建视频时 `characters` 最多 2 个，并固定使用角色所属上游账户。
- Seedance 2.0：支持 `doubao-seedance-2.0-{mini|fast|pro}-{480p|720p|1080p}` 与 `doubao-seedance-2.0-pro-4k`；创建时 `seconds` 为 4-15 的整数，入口兼容 JSON 数字或整数字符串，并向 Seedance 兼容上游发送字符串。
- 扁平素材字段：`image_url`、`first_image_url`、`last_image_url`、`reference_images`（最多 9）、`reference_videos`（最多 3，仅公网 URL）、`reference_audios`（最多 3，必须同时有图片或视频）。首尾帧不能与参考图/参考视频同用。
- 火山 `content[]`：支持 `text`、`image_url`、`video_url`、`audio_url`；媒体值可为字符串或 `{\"url\": \"...\"}`，角色使用 `first_frame`、`last_frame`、`reference_image`、`reference_video`、`reference_audio`。不能与等价顶层 prompt/素材字段混用。
- 有 `image_url`、首尾帧或参考视频时，画幅跟随素材，`ratio/aspect_ratio` 会被忽略。签名素材 URL 参与请求哈希，但不写入持久化任务元数据。

客户端回调发送 `video.completed` 或 `video.failed` 事件，并携带 `X-Sub2API-Event-ID`、`X-Sub2API-Timestamp`、`X-Sub2API-Content-SHA256`、`X-Sub2API-Signature`。目标必须是可解析到公网地址的 HTTPS URL；失败按冻结重试窗口处理，管理员可在 Callback 队列重试未过期的失败或隔离投递。

部署示例见 `deploy/config.example.yaml`。本地配置测试只加载配置，不启动后台服务、不连接生产数据库。总开关并不能跳过服务器启动时的迁移，因此不得用启动后端来代替只读检查。

## 3. 本地和隔离验收

在仓库根目录运行脚本测试：

```sh
node --test deploy/video-smoke.test.mjs
node deploy/video-smoke.mjs
```

第二条命令是 dry-run，不发网络请求。视频后端回归在 `backend` 目录运行：

```sh
go test -p 2 ./internal/service ./internal/handler ./internal/observability ./internal/config -run Video -count=1 -timeout=3m
CI=true go test -p 1 -tags=integration ./internal/repository -run 'TestVideoRelease|TestVideoTask|TestVideoBudget|TestVideoCreateHTTP' -count=1 -timeout=5m
```

集成测试通过 Testcontainers 新建隔离 PostgreSQL/Redis。`CI=true` 让 Docker 不可用时明确失败，不记为通过。`TestVideoReleaseUpgradeFromPreVideoSchemaPreservesExistingData` 模拟文件名排序在 238 之前的基线并升级；这不证明目标生产环境的实际已应用集合。通过 `SUB2API_TEST_POSTGRES_IMAGE` 指定已确认的目标 PostgreSQL 版本再验收。

进程故障用例真正终止测试子进程：提交成功但本地未记录时保持未知/冻结；资金已提交但未 ack 时恢复，不重复扣费。outbox 用例会先断言未过期租约拒绝接管，再仅调整隔离夹具的 claim 时间以模拟到期。它不是生产 kill 演练。

浏览器验收脚本为 `frontend/build-tools/video-release-browser.mjs`，需要 Playwright 和 Chromium/Chrome。先在 `frontend` 启动只连无效本地代理的测试服务：

```sh
VITE_DEV_PROXY_TARGET=http://127.0.0.1:9 npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
```

再从仓库根目录运行：

```sh
node frontend/build-tools/video-release-browser.mjs
```

可通过 `NODE_PATH` 指定已有 Playwright 包目录、`CHROME_PATH` 指定浏览器、`VIDEO_BROWSER_OUTPUT` 指定截图目录。脚本使用独立会话和 mock API，阻止跨域网络；不使用个人登录态。默认截图在 `/tmp/video-release-browser`。结束后关闭测试 Vite 服务。浏览器验收不等于真实后端端到端通过。

## 4. 真实收费 smoke（另行授权）

先确认环境、上游账户、模型/尺寸/秒数、报价、测试账户余额与 Key 额度、费用上限，以及第二个独立用户。凭据通过受控环境注入，不出现在命令参数、源码或报告中。

必需环境变量：`VIDEO_SMOKE_BASE_URL`、`VIDEO_SMOKE_KEY`、`VIDEO_SMOKE_OTHER_KEY`、`VIDEO_SMOKE_MODEL`、`VIDEO_SMOKE_SECONDS`、`VIDEO_SMOKE_SIZE`、`VIDEO_SMOKE_EXPECTED_COST_USD`、`VIDEO_SMOKE_MAX_COST_USD`。

只有获授权后，设置 `VIDEO_SMOKE_AUTHORIZED=yes` 并执行：

```sh
node deploy/video-smoke.mjs --run
```

脚本只使用一个幂等 key，最多三次 POST 分别验证初次创建、相同 body 重放、不同 body 冲突；轮询有上限。提交不确定或断言失败即停止，不更换 key，不盲目删除未结算任务。报告只保留本地任务 ID、幂等 key、校验结果和下载摘要，不保留媒体、提示词、凭据或原始错误响应。

费用参数仅用于核对已确认的报价，**不是服务端硬消费上限**。运行前必须配置独立测试 Key 的实际额度，不能用脚本预算字段替代资金风控。若服务端幂等存在缺陷，重复 POST 仍可能产生额外成本，这正是测试必须受控的原因。

成功报告为 `protocol_pass_accounting_pending`。完成后，用确认环境的只读数据库角色执行 `deploy/video-smoke-reconcile.sql`，传入报告的 `task_id` 和准确的 `user_id`，并与运行前记录对账。必须确认：仅一个 task/hold、一条 capture usage、余额只扣一次、冻结额归零、结算 outbox 收敛、删除完成。失败或没有财务证据不能记为完整通过。

## 5. 异常处理

- `submission_unknown`：保留冻结金额，不再次 Create。通过管理页和精确上游证据走既有独立审批；没有证据就保持隔离。
- `capture_pending/release_pending`：检查 outbox、任务事件、Worker 和数据库租约，使用已有重试结算入口。不要直接改余额或状态。
- `requested/deleting/delete_failed`：检查上游删除错误和账户可达性，修正后通过现有删除重试处理；不能以数据库删行代替删除完成。
- 下载失败：检查代理、上游和超时；不能因下载故障退款或重建任务。
- 密钥/账户身份变化：停止该账户新调度，保留承载既有任务的身份。禁止绕过归属、身份版本和权限校验。
- callback 403：检查 `gateway.video.callback.enabled` 和 `GATEWAY_VIDEO_CALLBACK_SIGNING_SECRET`；webhook 401/400：检查账户 webhook 密钥、标准签名头、时间窗口和事件类型。

完整告警处置见 `deploy/monitoring/video-runbook.md`。所有输出应脱敏，不导出 prompt、凭据、上游原始响应或数据库全量内容。

## 6. 发布和回滚

1. 核对实际已应用迁移、目标数据库版本、备份可恢复性和维护窗口。迁移新增集合为 238-254、264、265_video_failed_auto_release.sql 与 266_video_task_provider_url.sql；后两项是原生视频迁移，不是已删除的同编号 Grok SQL。不重排、不跳过 checksum。
2. 在目标版本的隔离库演练升级与原有账户/余额保持，完成约定规模的负载及告警接收验证。
3. 获得生产操作授权后停止旧实例写入，执行迁移并统一部署。先关闭创建验证健康和恢复 Worker；需要回调时再单独开启 callback Worker，然后执行获批准的 smoke。
4. 只有基础闭环、资金、权限、恢复及监控证据通过后，才按批准范围开启创建。
5. 放流前失败保持关闭，可恢复经演练的版本/备份；产生真实新任务后先停止新建，保留能处理新 task/outbox 的恢复版本。不得直接回滚数据库或让旧版本接管新义务。

迁移 240 包含两处 `ALTER COLUMN tier_label TYPE VARCHAR(128)`，按现有 CI 规则需要 PR 的 `breaking-migration` 标签，且本次必须停机发布，不能蓝绿混跑。提交前运行 `backend/scripts/check-migration-gate.sh HEAD --worktree` 确认命中项，再按已审批的停机发布方案使用 `--allow-breaking` 验证；不带 `--worktree` 的检查不覆盖未提交文件。保留 SQL 原文，避免使已应用的开发库发生 checksum mismatch。

Provider 身份提出、批准、拒绝及撤销沿用系统 `step_up_enabled` 设置；开启时要求近期 TOTP 验证。长期凭据披露实时复核数据库中的归属与已知别名，检查失败时不返回长期密钥，但保留原任务查询。上游视频 URL 的短期签名认证由上游负责，本站继续代理该 URL，不新增本站签名。

本手册不要求新旧 writer 无停机混跑、Grok 存量盘点、归档或更正。目标环境、费用授权、生产备份及真实容量数据未确认时，停在发布门禁，不追加外围功能。
