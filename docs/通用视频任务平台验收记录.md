## 4. 二进制输入验收

平台输入层和 Provider 能力层已经分离：

1. multipart 文件 role 使用长度不超过 64 的小写 ASCII 标识符。
2. handler 对标量字段、保留字段、危险 role 名和重复 part 做严格校验。
3. spool 对合法 role 使用同一套 AEAD chunk 加密、MIME sniff、大小限制和 SHA-256 管线；图片从加密 reader 解码真实宽高并校验目标 size。
4. `VideoCapabilities.InputRolesByOperation` 决定 operation 和 role 的允许关系；`InputMIMETypes` 和 `MaxInputBytes` 决定媒体约束。
5. capability 校验发生在任务和 hold 创建之前。
6. 远程和上传的图片 `input_reference` 进入既有图片审核；上传图片从加密 reader 构造有界审核输入，8 MiB 上限与 capability catalog 一致，审核阻断发生在任务/hold/Submit 前。
7. OpenAI 默认能力只允许 generate 的图片 `input_reference`、edit 的 `source_video` 和 character create 的 `character_clip`。
8. `depth_map` 等未来 Provider role 可由 capability/adapter 增加，不需要修改 spool、任务表或公共生命周期。

因此，“支持其他二进制输入”表示通用平台可安全接收 Provider 声明的 role，不表示把任意附件无条件转发给 OpenAI。

## 5. 媒体零持久化检查

- migration 中不存在 `video_assets` 表。
- service、handler 和 repository 中不存在 `AssetStore` 依赖。
- multipart 未调用 `ParseMultipartForm`；文件 part 通过 `multipart.Reader` 直接进入加密 spool。
