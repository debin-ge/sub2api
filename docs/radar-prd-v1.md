## 1. 文档目的

本文档定义 Sub2API「模型雷达」v1 的产品目标、用户范围、功能需求、数据口径、交互规则、异常处理、验收标准及上线要求，作为产品、设计、前端、后端、测试和运维共同评审与交付的基准。

本文档描述“做什么”和“达到什么标准”；具体技术实现以配套实施方案为准。

---

## 2. 产品背景

Sub2API 是用于分发和管理 AI 产品订阅配额的 API 网关平台。当前用户需要分别查看站内账号用量、模型评测网站和厂商状态页，才能回答以下问题：

1. 当前 Claude、OpenAI 等上游服务是否正常？
2. 不同订阅套餐的真实额度大致是多少，当前利用率如何？
3. 主流模型的智能、编码和代理能力是否出现变化？

信息分散、更新频率不同、统计口径不一致，导致用户判断成本高。模型雷达将站内聚合数据与公开外部数据源整合到一个无需登录的页面中，提供统一、透明、可追溯的观察入口。

---

## 3. 产品定义

### 3.1 一句话定义

模型雷达是 Sub2API 的公开数据首页，集中展示 AI 服务健康状态、订阅额度利用与反推上限，以及主流模型能力指数和排名趋势。

### 3.2 核心价值

| 用户价值 | 产品能力 |
|---|---|
| 快速判断上游是否可用 | 服务健康状态聚合 |
| 了解套餐真实使用空间 | 额度利用率、消费和上限反推 |
| 识别模型能力变化 | 多维指数、90 天趋势和 Elo 排名 |
| 判断数据是否可信 | 样本量、标准差、更新时间和来源披露 |

### 3.3 产品原则

1. **公开透明**：核心页面无需登录即可访问。
2. **可信优先**：样本不足或离散度过高时不展示确定性结论。
3. **来源可追溯**：外部数据必须展示来源和更新时间。
4. **隐私保护**：仅展示聚合结果，不暴露账号、用户、API Key 或单账号用量。
5. **渐进披露**：首屏展示核心结论，详细数据通过趋势、Tab 和弹窗查看。
6. **故障可降级**：单一数据源失败不得导致整页不可用，旧数据须明确标记时间。

## 4. 产品目标与非目标

### 4.1 v1 目标

1. 将 `/` 替换为公开模型雷达首页，同时保留 `/home` 原首页。
2. 展示 Claude 与 OpenAI 相关服务的最新健康状态。
3. 按平台和订阅套餐聚合站内账号，展示 5 小时与 7 天额度数据。
4. 使用统一可信度规则反推套餐额度上限。
5. 接入 Artificial Analysis 与 LMArena，展示模型能力对比和趋势。
6. 支持中英文、明暗主题、手动重试和自动刷新。
7. 在多数据源部分失败时仍提供可理解、可恢复的页面体验。

### 4.2 非目标

以下内容不纳入 v1：

- 用户登录、注册、购买、充值或套餐推荐流程改造；
- 对单个账号或单个用户公开用量明细；
- 对“模型降智”给出因果结论或厂商责任判断；
- 新增数据库业务表或提供长期历史数据仓库；
- 接入 Aider、LiveBench、SWE-bench 等更多评测源；
- 服务事故时间线、通知订阅或 SLA 承诺；
- 超过 7 天的额度历史和超过 90 天的模型指数历史；
- 日语国际化；
- 面向公众开放管理刷新能力。

### 4.3 后续版本候选

- 更多 benchmark 数据源与交叉验证；
- 服务事故时间线和告警订阅；
- 额度桶筛选、排序、分组折叠和虚拟滚动；
- 更长期的额度趋势；
- 平台或套餐对比工具；
- 管理端可视化配置和数据质量面板。

## 5. 用户与使用场景

### 5.1 目标用户

| 用户类型 | 核心诉求 | 典型行为 |
|---|---|---|
| AI API 使用者 | 判断故障是否来自上游，选择当前可用模型 | 查看服务健康与模型能力 |
| 订阅套餐使用者 | 了解套餐额度和当前利用水平 | 查看额度卡片、7 天趋势和详情 |
| Sub2API 运营/管理员 | 观察数据源、额度聚合和系统状态 | 查看数据时间，必要时手动刷新 |
| 社区研究者/访客 | 比较模型公开评测表现 | 查看三维指数、趋势和 Elo 排名 |

### 5.2 核心用户故事

- 作为访客，我希望无需登录就能看到上游服务状态，以便快速判断调用异常是否为厂商故障。
- 作为套餐使用者，我希望看到同套餐账号的平均利用率和反推上限，以便理解套餐真实容量。
- 作为谨慎的用户，我希望看到样本量、标准差、时间和数据来源，以便判断结论可信度。
- 作为模型使用者，我希望比较多个模型的能力指数并查看 90 天变化，以便选择模型。
- 作为管理员，我希望可以临时关闭雷达或触发数据刷新，以便处理异常数据源。

### 5.3 典型用户路径

1. 用户访问 `/`，无需登录进入模型雷达。
2. 用户先查看服务健康，判断受支持的模型平台是否存在故障，并可查看最近 30 天逐日状态。
3. 用户滚动或通过锚点进入额度雷达，查看目标套餐的 5 小时利用率和反推上限。
4. 用户点击套餐卡片，查看 5 小时/7 天详情、模型利用率和消费分解。
5. 用户进入降智雷达，对比模型三维指数、90 天趋势或 LMArena Elo 排名。
6. 用户在页尾查看数据来源、刷新频率和免责声明。

- 弹窗最大高度不超过视口 90%，内容区域可滚动；

## 8. 详细功能需求

### 8.1 FR-01 公开访问与路由兼容

#### 需求描述

- 用户访问 `/` 时直接进入模型雷达，不出现登录墙。
- `/home` 继续指向原首页，不得重定向至模型雷达。
- 后端受限模式的允许路径必须包含 `/`。
- 页面登录入口沿用现有系统行为，但查看雷达本身不需要登录。

#### 验收标准

- 未登录用户访问 `/` 可看到完整雷达页面。
- 未登录用户访问 7 个公开雷达接口不会收到 401/403。
- `/home` 的页面内容和现有自动化测试不受影响。

### 8.2 FR-02 页面头部、Hero 与锚点导航

#### 需求描述

- Header 提供“服务健康 / 额度雷达 / 降智雷达”三个锚点。
- 点击锚点后平滑滚动到对应模块。
- 当前语言支持 `zh`、`en`；不新增 `ja`。
- 支持现有明暗主题切换。
- Hero 展示产品标题、简述和页面最近一次成功获取数据的时间。
- 页面刷新时间与各数据源更新时间必须区分：前者代表客户端拉取，后者代表源数据新鲜度。

#### 验收标准

- 三个锚点均定位准确，目标标题不被 Sticky Header 遮挡。
- 切换语言后页面关键文案即时更新，且无缺失 key。
- 切换主题后图表、卡片、表格和弹窗均可读。

### 8.3 FR-03 服务健康

#### 展示对象

v1 展示 6 个具有可信官方状态源的平台卡片：

1. Anthropic；
2. OpenAI；
3. Windsurf；
4. DeepSeek；
5. Kimi；
6. MiniMax。

Anthropic 和 OpenAI 卡片分别聚合其 API、Claude Code/Codex Web 等受支持组件，并按最严重状态展示。无可靠状态源的平台（例如 GLM）不生成虚假的“状态未知”卡片。若上游组件命名发生变化，无法识别时仅影响对应平台，不得错误映射到其他服务。

#### 状态枚举

| 原始状态 | 中文展示 | 视觉级别 |
|---|---|---|
| `operational` | 正常 | 成功/绿色 |
| `degraded_performance` | 性能降级 | 警告/黄色 |
| `partial_outage` | 部分故障 | 警告/橙色 |
| `major_outage` | 重大故障 | 严重/红色 |
| `under_maintenance` | 维护中 | 信息/蓝灰色 |
| 未知或无数据 | 状态未知 | 中性/灰色 |

#### 卡片内容

- 服务名称；
- 当前状态；
- 最近更新时间；
- 数据源链接；
- 数据陈旧标识；
- 最近 30 天逐日状态日历条；
- 日期悬浮、键盘聚焦或点击后展示当日状态和事故详情；
- 若数据可用，可展示 90 天可用率及最近事故；字段缺失时不占位、不虚构。

#### 数据频率

- Claude Statuspage：每 30 分钟抓取；
- OpenAI Statuspage：每 30 分钟抓取；
- Windsurf、DeepSeek、Kimi、MiniMax 官方状态源：每 30 分钟抓取；
- 前端公开响应可缓存 5 分钟。

#### 验收标准

- 正常数据下展示 6 张平台卡片且名称稳定，每张日历条包含 30 个日期。
- 每种已知状态均有对应中文、英文文案与可区分的视觉状态。
- 缺失的历史日期显示“状态未知”，不得把未知解释为正常。
- 单一状态源失败时，其余模块和服务卡仍可展示。
- 平台目录接口失败时，健康接口中已有的平台数据仍可展示。

### 8.4 FR-04 额度桶聚合与卡片

#### 分桶规则

额度数据按 `{platform}/{plan_tier}` 聚合：

| 平台 | 套餐来源 | 缺省处理 | 示例 |
|---|---|---|---|
| Anthropic | `plan_slug` | `generic` | `anthropic/max_20x` |
| OpenAI | `plan_type` | `unknown` | `openai/pro` |
| Antigravity | `plan_type` | `basic` | `antigravity/ultra` |

任何公开结果中不得包含账号 ID、凭据、用户 ID、邮箱或可回溯到单账号的信息。

#### 卡片内容

每个额度桶卡片默认展示：

- 用户友好的套餐名称；
- 桶内账号数量；
- Anthropic 展示 5 小时平均利用率，OpenAI 暂时仅展示 7 天平均利用率；
- 利用率进度条；
- 当前展示窗口的反推上限及标准差；
- 7 天利用率 Sparkline；
- “查看详情”入口。

#### 利用率颜色

| 区间 | 颜色 |
|---|---|
| `< 40%` | 绿色 |
| `40%–<60%` | 黄色 |
| `60%–<80%` | 橙色 |
| `≥ 80%` | 红色 |

颜色只表达利用率高低，不直接代表套餐好坏或故障。必须同时显示数字，不能仅依赖颜色传达信息。

#### 样本提示

- 当桶内账号数 `< 3` 时，卡片展示小样本警告 `⚠ n=x`。
- 小样本警告是提示信息，不等同于反推结果必然无效。
- 反推结果是否展示，以有效反推样本与离散度规则为准。

#### 验收标准

- 额度桶按平台与套餐正确聚合，不跨套餐混合。
- 每张卡片使用 5 小时指标作为主指标。
- 趋势尚未加载时显示局部加载状态，不阻塞其他卡片。
- 反推不可用时显示“样本不足/数据离散”，不得显示 `$0` 或猜测值。

### 8.5 FR-05 额度上限反推与可信度

#### 计算口径

单账号在指定窗口内的候选上限：

```text
候选上限（USD） = 窗口消费金额（USD） ÷（利用率 ÷ 100）
```

OpenAI 周窗口不得使用滚动 7 天消费代替实际额度周期。聚合器必须先读取账号本次每周限制的下一次重置时间，以 `下次重置时间 - 7 天` 作为本周期起点，并统计该起点至本次聚合时刻的模型与消费。单模型校验公式为：

```text
单模型候选上限（USD） = 模型消费金额 ÷（模型消费占账号总消费比例 × 账号周消耗比例）
```

同一账号先计算每个模型的候选上限，再对模型候选上限取算术平均，得到一个账号候选上限；同一套餐桶内再对各账号候选上限取算术平均。模型数和账号数均不得作为加权系数。

#### 有效样本

仅当账号满足以下条件时参与反推：

- 账号属于目标额度桶；
- 对应窗口利用率 `≥ 5%`；
- 消费、利用率等输入数据有效且非负；
- 被动用量数据可读取。

#### 可信结果判定

对同一桶、同一窗口的候选上限计算均值与标准差。只有同时满足下列条件才展示反推上限：

1. 有效样本数 `≥ 2`；
2. 均值 `> 0`；
3. `标准差 ÷ 均值 ≤ 0.3`。

否则 `inferred_limit_usd` 返回空值，并向用户展示非确定性文案。

#### 展示规则

- 有效结果：`$均值 ± $标准差`，金额按页面规则取整展示；
- 无效结果：显示“样本不足”或统一的“暂无可信结果”；
- 详情中同时展示有效样本量；
- 页面必须展示免责声明：“反推上限为统计估算值，不应作为关键决策依据”。

#### 验收标准

- 利用率低于 5% 的账号不参与反推。
- 有效样本少于 2 个时返回空值。
- 离散系数大于 0.3 时返回空值。
- 边界值 5%、样本数 2、离散系数 0.3 按“有效”处理。
- 同一输入重复计算得到一致结果。

### 8.6 FR-06 额度趋势

#### 需求描述

- 每 15 分钟生成一次额度桶快照。
- 每个桶最多保留最近 7 天数据，预计稳定为约 672 个点。
- 卡片 Sparkline 展示最近 7 天的 5 小时平均利用率。
- 用户可按桶请求 1–7 天趋势，v1 默认 7 天。
- 趋势数据按时间升序排列。

#### 验收标准

- 超过 7 天的数据不会继续出现在公开趋势中。
- 空趋势显示“暂无趋势数据”，不渲染错误图表。
- 相同时间点不得因多实例重复调度产生明显重复快照。

### 8.7 FR-07 额度详情弹窗

#### 入口与关闭

- 点击卡片或“查看详情”打开弹窗。
- 点击关闭按钮或遮罩空白处关闭。
- 支持键盘 `Esc` 关闭，并在关闭后将焦点返回触发元素。

#### 内容

- 套餐名称、桶内账号数和快照时间；
- 5 小时 / 7 天 Tab；
- 当前窗口平均利用率、最小—最大利用率、平均消费、反推上限；
- 有效样本量与小样本提示；
- 模型消费分解：模型、平均消费、平均请求数、消费占比；
- Anthropic 桶在 7 天 Tab 中展示 Sonnet/Fable 分模型利用率（有数据时）；
- 无模型分解数据时显示空态。

#### 验收标准

- 切换 5 小时/7 天时所有窗口相关数据同步切换。
- 非 Anthropic 桶不展示 Sonnet/Fable 区域。
- 弹窗内容超高时内部可滚动，头部和关闭入口持续可见。
- 弹窗打开时焦点被限制在弹窗内，背景不可被键盘误操作。

### 8.8 FR-08 模型三维指数概览

#### 数据源与指标

Artificial Analysis 提供以下指标：

- Intelligence Index（智能指数）；
- Coding Index（编码指数）；
- Agentic Index（代理指数）；
- 可选价格字段和模型元数据。

#### 展示规则

- 雷达图最多同时展示 6 个配置模型，避免图表不可读；
- 展示模型名称、厂商和三个指数；
- 指标范围按数据源定义展示，v1 预期为 0–100；
- 数据源主列表每 6 小时刷新；
- 缺少某个指标的模型不应以 0 冒充真实分数，应跳过该维度或模型并记录异常。

#### 产品措辞

“降智雷达”仅表示公开 benchmark 指标随时间的变化，不代表已证明模型发生服务端降级。页面不得使用“已降智”“偷算力”等确定性因果措辞。

#### 验收标准

- 有效数据下雷达图展示不超过 6 个模型。
- 图例可区分模型，明暗主题下均可读。
- 缺失数据不会导致整个模块崩溃。

### 8.9 FR-09 单模型 90 天趋势

#### 验收标准

- 加载单条趋势失败仅影响趋势区域，不影响雷达图和排名表。
- 无数据时显示明确空态和数据源更新时间。

### 8.12 FR-12 页面状态与降级

#### 首次加载

- 页面首次请求期间展示加载状态。
- 主体数据尚未返回前不得闪现错误的空卡片或零值。

#### 全量失败

- 当首次加载所有核心数据均不可用时，展示错误标题、简短原因和“重试”按钮。
- 不向普通用户直接展示堆栈、内部地址、密钥或数据库错误。

#### 局部失败

- 单个接口或数据源失败时，仅对应模块展示局部错误/空态。
- 已有旧数据时继续展示旧数据，并显示最近成功更新时间和“数据可能已过期”提示。
- 抓取失败不得覆盖最近一次成功数据。

#### 空数据

| 场景 | 用户文案/行为 |
|---|---|
| 尚无额度快照 | “暂无额度数据，首次聚合将在服务启动后约 15 分钟内完成” |
| 反推不可信 | “暂无可信结果”或“样本不足” |
| 趋势为空 | “暂无趋势数据” |
| benchmark 为空 | “等待评测数据” |
| 状态组件未识别 | “状态未知” |

### 8.13 FR-13 国际化与主题

- 金额统一标注 USD 或使用 `$`，不进行汇率换算。
- 术语统一：Utilization=利用率、Inferred Limit=反推上限、Bucket=桶、Sample Size=样本量、Standard Deviation=标准差。
- 图表颜色在明暗主题下均需满足可读性，不以颜色作为唯一信息载体。

### 8.14 FR-14 自动刷新

- 页面提供 30、60、300、600 秒刷新间隔，默认 60 秒。
- 用户可开关自动刷新；偏好保存在浏览器本地。
- 自动刷新仅重新读取缓存后的公开数据，不直接触发外部源抓取。
- 刷新期间保留已展示数据，避免整页闪烁。
- 刷新失败时保留旧数据并提示，不清空页面。
- 避免并发重复刷新：上一轮未完成时不得无限叠加请求。

### 8.15 FR-15 管理能力（P1，可选交付）

- 管理员可通过运行时开关启用/停用雷达后台调度，默认开启。
- 停用调度不删除已有缓存；公开页面可继续展示旧数据并标记时间。
- 管理员可触发所有数据源和额度聚合立即刷新。
- 手动刷新接口必须要求 Admin 权限，并立即返回已触发任务列表，不等待所有后台任务完成。
- 重复点击需有防抖或任务锁，避免并发抓取。

## 9. 数据定义与业务规则

### 9.1 核心指标字典

| 指标 | 定义 | 单位 | 数据范围/备注 |
|---|---|---:|---|
| 平均利用率 | 桶内可获得用量数据的账号利用率算术平均 | % | 包含低于 5% 的账号；0–100，异常上游值需校验 |
| 最小/最大利用率 | 桶内账号利用率边界 | % | 详情展示 |
| 平均消费 | 桶内账号在窗口内消费金额平均值 | USD | 非负 |
| 候选上限 | 单账号消费 ÷ 利用率比例 | USD | 利用率 ≥5% 才计算 |
| 反推上限 | 候选上限的算术平均 | USD | 通过可信度判定才展示 |
| 反推标准差 | 候选上限的标准差 | USD | 与均值同时展示 |
| 有效样本量 | 实际参与反推的账号数 | 个 | 不等同于桶内账号数 |
| 消费占比 | 单模型平均消费 ÷ 桶内模型总消费 | % | 合计因四舍五入可不等于 100% |
| Elo | LMArena 社区盲测评分 | 分 | 使用源数据口径 |

### 9.2 时间窗口

- 5 小时窗口：用于卡片核心指标，体现近期状态；
- 7 天窗口：用于详情与额度趋势；
- 90 天窗口：用于模型 benchmark 日级趋势；
- 后端存储与接口时间统一为 ISO 8601 UTC；
- 前端按用户本地时区显示。

### 9.3 数据新鲜度

| 数据 | 正常更新频率 | 建议陈旧提示阈值 |
|---|---:|---:|
| 额度桶 | 15 分钟 | 超过 30 分钟未更新 |
| 服务健康 | 30 分钟 | 超过 60 分钟未更新 |
| AA 模型列表 | 6 小时 | 超过 12 小时未更新 |
| AA 模型趋势 | 24 小时 | 超过 48 小时未更新 |

陈旧提示阈值是产品展示规则；是否作为正式告警阈值需在上线前由运维确认。

### 9.4 数据保留

- 额度历史：滚动保留 7 天；

## 11. 非功能需求

### 11.1 性能

- 公开接口在缓存命中情况下，100 并发下 p95 响应时间目标 `< 100ms`；
- 首屏数据请求并行发起，趋势数据按需加载；
- v1 按约 20 个额度桶设计；超过 50 个桶时需评估分页或虚拟滚动；
- 单次外部响应体必须限制大小，避免异常源耗尽内存。

### 11.2 可用性与韧性

- 单个外部源失败不影响其他源和额度数据展示；
- 外部抓取网络错误和 5xx 可进行有限重试，4xx 不盲目重试；
- 多实例部署时，同一抓取或聚合任务同一周期只能由一个实例执行；
- 服务退出时后台调度应优雅停止；
- Redis 不可用时页面应返回可理解的错误或进程内旧数据，不得卡死。

### 11.3 安全与隐私

- 公开接口不得返回任何单账号或单用户标识和凭据；
- 外部 API Key 仅保存在服务端配置中，不得进入前端包、接口响应或日志；
- 日志中的账号标识应遵循现有日志脱敏规范；
- 管理刷新接口必须鉴权、授权并记录操作日志；
- 所有外部链接使用安全跳转属性，防止反向标签页控制；
- 查询参数必须校验，防止任意 Redis Key 访问、路径穿越或资源滥用。

### 11.4 可访问性

- 核心文本和交互控件满足 WCAG 2.1 AA 对比度目标；
- 所有按钮、Tab、下拉框和弹窗支持键盘操作；
- 图表提供可读标题、图例和必要的数据替代表达；
- 状态、趋势和告警不能只依赖颜色；
- 尊重用户的“减少动态效果”系统偏好。

### 11.5 兼容性

- 支持项目现行浏览器基线的最新两个主要版本；
- 桌面端和移动端均可使用；
- 不改变现有 `/home`、登录、主题和语言功能。

### 11.6 可观测性

至少记录并监控：

- 各数据源抓取成功/失败次数、耗时、HTTP 状态和最近成功时间；
- 额度聚合耗时、桶数量、跳过账号数量；
- 反推成功/拒绝数量及拒绝原因；
- 公开接口请求量、状态码和响应耗时；
- Redis 读写错误与雷达缓存内存量。

建议告警包括：数据源持续失败、聚合耗时异常、桶数量异常下降和数据长期未更新。

## 15. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 外部 API 限流或下线 | 降智/健康数据陈旧 | 控制频率、重试、保留旧数据、展示时间、监控告警 |
| 套餐识别错误或混桶 | 反推上限失真 | 严格分桶、离散度拒绝、样本提示、异常桶排查 |
| 低利用率放大误差 | 候选上限异常 | 仅纳入利用率 ≥5% 的账号 |
| 样本过少 | 结果不稳定 | 少于 2 个有效样本不展示；桶账号少于 3 个警告 |
| “降智”名称引发误读 | 用户误判因果 | 明确 benchmark 属性与免责声明，避免确定性措辞 |
| Redis 故障或数据丢失 | 7 天历史不可用 | 接受非关键数据可重建，提供错误态与重新聚合 |
| 多实例重复调度 | 重复请求和快照 | 使用分布式锁和任务幂等 |
| 桶数量增长 | 前端性能下降 | v1 监控，超过 50 个评估分页/虚拟滚动 |
| 公开聚合可被反推单账号 | 隐私风险 | 小样本警告之外，评审是否需最小公开桶阈值 |

## 16. 待确认事项

以下问题不阻塞 PRD 主体评审，但必须在进入最终开发或上线前确认：

1. **小桶隐私门槛**：当桶内仅 1 个账号时，公开平均消费和利用率可能等同于单账号数据。是否要求桶内账号数 `< 2` 或 `< 3` 时隐藏消费、利用率和模型分解？建议至少 2 个账号才公开聚合数值。
2. **反推失败文案**：是否区分“有效样本不足”和“数据离散度过高”，还是统一显示“暂无可信结果”？建议区分，提升透明度。
3. **服务第四张卡命名**：设计稿存在“Codex API / GPT API”两种表述。本文统一为“OpenAI API”，需产品最终确认。
4. **90 天可用率**：Statuspage summary 未必直接提供该字段。v1 是否隐藏，还是另行计算？建议无可靠数据时隐藏。
5. **默认模型列表**：Artificial Analysis 的 10 个配置模型需要在上线前按真实可用 slug 校验，并明确雷达图默认展示的最多 6 个模型。
6. **数据源授权**：确认 Artificial Analysis 与 LMArena 数据的展示、缓存、署名和外链符合其许可与服务条款。
7. **产品分析埋点**：确认项目是否已有匿名分析方案；若无，v1 只使用访问日志和服务指标。
8. **陈旧数据阈值**：本文给出建议值，需运维确认是否与告警阈值一致。
9. **管理端是否纳入首发**：管理开关与手动刷新在实施方案中为可选 PR，需要明确首发范围。

## 17. 术语表

| 术语 | 定义 |
|---|---|
| 额度桶（Bucket） | 相同平台与套餐层级账号组成的匿名聚合分组 |
| 利用率（Utilization） | 上游返回或系统计算的窗口额度使用百分比 |
| 反推上限（Inferred Limit） | 根据消费与利用率统计估算的套餐美元等价值上限 |
| 有效样本 | 满足利用率及数据质量要求、实际参与反推的账号样本 |
| 标准差 | 候选上限离散程度的统计量 |
| 离散系数 | 标准差除以均值，用于判断反推结果是否稳定 |
| Intelligence Index | Artificial Analysis 的综合智能能力指标 |
| Coding Index | Artificial Analysis 的编码能力指标 |
| Agentic Index | Artificial Analysis 的代理/任务执行能力指标 |
| Elo | LMArena 基于社区盲测对战结果计算的相对评分 |
| 陈旧数据 | 已超过预期更新周期，但仍作为降级结果展示的最近成功数据 |
