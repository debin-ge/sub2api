# 媒体任务安全修复说明

本次对应 SEC-001、SEC-003、SEC-004、SEC-005、SEC-006、SEC-007。代码修复与本地测试不代表已部署；数据库迁移需要在后续受控发布时执行。

## 行为变化

### Grok 视频完成结算（SEC-001）

状态查询与内容查询本身继续免费。它们首次观察到视频完成时，明确按视频生成类型结算，保留现有任务归属、Redis claim、数据库账务幂等和 outbox。

不会自动重算或追扣历史零元账单。历史记录可能缺少视频计量数据，需先核对可信任务与供应商证据，排除合法免费情况，再采用独立、幂等、经审核的账务调整；不要删除原去重记录后重放。

### Flova 状态与支出边界（SEC-003、SEC-004）

当前供应商接口没有可验证的任务级硬预算，初始 `/chat` 本身就可能执行收费动作。因此安全版本在任何供应商调用前拒绝新的 Flova 创建，已有账号的自动确认设置不再授予付费权限。此行为不是一个默认关闭、管理员可绕过的预算开关。

已有任务仍支持只读轮询和可用内容访问。轮询不再调用 `/chat` 恢复任务；项目、运行、资源状态在带版本/租约守卫的任务事务中持久化，原有供应商任务标识保持稳定，新增资源标识单独存入私有 JSON 状态，避免超过旧任务标识长度上限。待确认动作按唯一标识记录为受阻。不会把请求时长伪装成实际输出计量。旧任务完成时仍按既有冻结报价政策处理用户账单，供应商成本独立核对。

已被旧代码丢弃的新运行 ID 不能凭空恢复。此类任务需要可信的供应商只读证据；不能将用户输入直接绑定为新运行，也不能把旧消费当零。重新开放创建/自动执行前，需要明确供应商预算执行能力、动作幂等及未知结果恢复契约，并补齐对应实现和隔离验收；仅增强提示词或逐次比较单价不够。

### 提交结果未知与供应商成本（SEC-005）

用户在规定期限后退款的政策保留。供应商是否受理、是否收费则通过独立台账持续跟踪，不因用户退款就解释为零成本。只读恢复不得重新创建或恢复付费动作；供应商报告失败也不等于没有收费。

每用户最多 3 个、每供应商账号最多 20 个风险名额，跨 API Key 和实例共享。名额在首次提交前通过数据库行锁保护的事务占用，覆盖尚未确认受理的任务与未核销成本；确认受理的正常运行任务不占提交名额。所有本地执行超时后的退款都进入成本核对，取消接口返回成功同样不能证明供应商没有费用。

只读恢复每批最多处理 4 条、每条查询最多 10 秒、最多尝试 12 次；停止自动查询后记录仍保持未核销。供应商不支持恢复、账号身份变化、查询失败和结果不存在分别记录，不转成零成本。历史回填结合未知提交标记和不可变任务事件，不依赖可被后续删除操作清空的最后错误码。

管理员核销只处理供应商成本证据，不改变用户余额：

- `GET /api/v1/admin/videos/provider-costs`：按 `state`、`after`、`limit` 查看，最多 100 条，默认未核销。
- `POST /api/v1/admin/videos/provider-costs/:id/resolve`：必须提供 `Idempotency-Key`，请求体包括 `expected_version`、`state`、`amount`、`currency`、`evidence`。状态只能是 `resolved_no_charge`（金额为 0）或 `resolved_cost_recorded`（正金额），币种为 `USD`、`CNY`、`CREDITS`。证据至少 20 个字符且不超过 2048 字节。
- 操作者取当前管理员身份；版本冲突或同幂等键不同内容返回冲突。核销应引用可信供应商账单或查询证据，不能仅凭任务失败、取消成功或查无结果填写零费用。

### Ark 列表（SEC-006）

公开状态与平台筛选下推数据库，再按 `page_num/page_size` 分页。`completed` 且扣费未完成的任务仍属于 `running`，只有 `captured` 才显示 `succeeded`。不再循环读取用户全部历史。

- 保留最多 50 页、每页最多 100 条，最大 offset 为 4900。
- 每用户每分钟最多 60 次列表读取，所有 API Key/实例共享 Redis 计数。超限返回 429 和 `Retry-After: 60`；限流存储故障拒绝读取。
- 查询上下文最多 3 秒，新增按公开状态过滤的部分表达式索引。
- 越过末页的空页不再返回推测的 `total`，避免把页码推导值冒充总量。

### 异步图片准入（SEC-007）

配置了 pending 上限时，先按用户在共享 Redis 中原子预留，再读取请求体、审核、创建任务；后台任务接管预留，终态保存与释放使用所有权检查。Redis 故障不回退本地计数。配置显式关闭上限的语义保留。

全流程使用同一个绝对截止时间，覆盖预处理、生成、结果上传和存储；结果保留期与准入占用期分离。进程退出由有界预留期处理，旧任务记录保持可读。依赖若不遵守取消，仍不能仅凭本地超时证明供应商停止了工作。

## 后续发布边界

1. 新增迁移 278、279、280；279 和 280 的索引文件使用非事务并发索引迁移，并支持清理失败重试留下的无效索引。先在隔离 PostgreSQL 验证迁移、执行计划和回滚策略，禁止直接用生产数据做压力验证。
2. 任务 worker 与账务 outbox worker 需要协调切换，避免旧版本绕过新增准入或在结算时遗漏成本台账；旧 Flova worker 还可能发起自动确认或丢弃状态。暂停接收、等待在途操作达到可恢复状态后，再迁移和切换全部实例。
3. 异步图片切换前停止新增接收并排空旧任务，或者采用等效的全实例协调切换。旧进程的本地计数无法自动纳入新 Redis 预留。
4. Redis 使用现有 standalone 客户端。图片预留涉及多键原子操作，迁移到 Redis Cluster 前必须完成同槽键设计与兼容测试。Redis 数据丢失后，不能把空集合视为没有活动任务，应先停止新增接收、核对或排空旧任务。
5. 保留历史账务事实，不自动补扣旧用户、不伪造供应商零成本，也不无限冻结用户资金。

这些本地测试不能代替实际 PostgreSQL 迁移/计划验证、供应商账单核对或发布后的监控。

### CI 迁移失败修复与隔离验证（2026-10-13）

本地使用临时 PostgreSQL 16 和 Redis 容器，实际执行全部初始化迁移及以下 CI 对应套件，均通过：

```sh
SUB2API_TEST_POSTGRES_IMAGE=postgres:16-alpine go test -tags=integration ./internal/repository -run 'Test(VIP|AuthCacheInvalidationTriggers|GroupRepoSuite|MigrationsRunner)' -count=1
SUB2API_TEST_POSTGRES_IMAGE=postgres:16-alpine go test -tags=integration ./internal/repository -run 'Video|BalanceHold|UsageBilling' -count=1
```

迁移分句、执行模式和校验和的针对性单元测试也通过。临时容器已清理；未连接项目或生产数据库，未调用真实供应商，未部署。该记录是本地验证结果，不表示远端 CI 已重新执行。

## Flova 创建重新开放（2026-10-16，对 SEC-003/004 的有意例外）

运营方决定在 Flova 仍然没有任务级硬预算的情况下重新开放创建。完整契约见 `docs/Flova 成本约束设计.md`。

**本节对上文前提的回应**

| 前提 | 处理 |
|---|---|
| 供应商预算执行能力 | 不存在任务级上限。运营方实测确认：Flova 每次发起视频生成会先冻结预估金额，余额不足时无法发起。账号余额因此限制了可发起的生成次数。余额可能被结算差额拉成负数，运营方决定不考虑透支底线。 |
| 动作幂等 | 每个任务最多一次自动确认。授权（`resume_action_key`）先由观测事务落库，worker 在提交成功之后调用一次 resume。调用失败、结果未知或进程崩溃都不重试；之后再出现的任何确认都会被阻断。 |
| 未知结果恢复 | 单账号串行：账号上有在途任务或未结清的 Flova 成本记录时，不接新任务。SEC-013 修订后，余额差仅是观测；包括 `/chat` 结果未知的情形在内，都需供应商结束和最终账务凭据才能人工核销。 |
| 不是管理员可绕过的开关 | 没有运行时开关，行为随代码版本发布。旧凭据 `auto_confirm_high_cost`、`auto_confirm_credits_max` 不再授予任何权限。 |

**残余风险（平台承担）**
- 单次 run 失控时的花费没有硬上限，只能事后发现：运行中的余额监控和终态后的对账，在花费超过预算时把账号熔断 24 小时，需人工解除。用户始终按冻结报价结算。
- 账号必须专用于本网关。如果账号同时被别处使用，余额差的归因会失真。
- 预算内的确认只放行恰好 1 个视频、模型和分辨率一致、单价不超过价格表 ×（1 + 容差）、并且报价加上已观测花费不超过预算的情形。

## SEC-008 / 011 / 012 / 013 / 014 修复

- **SEC-008**：匿名支付 `orders/verify` 和 `orders/resolve` 共用固定 IP 额度（20 次/分钟）。Redis 不可用时返回 429 和 Retry-After，查询不会进入订单服务；原请求体上限和面板限流保留。
- **SEC-011**：Gemini 创建缓存取得的用户、API Key 和账号并发槽随实际 handler 完成释放。客户端取消只取消等待和未发送的创建，不释放仍在执行的上游操作所占槽；释放函数幂等，错误及 panic 路径也释放。
- **SEC-014**：`billing.inflight_reservation.enabled=true` 时，固定费用的余额、订阅和 API Key 预留能力缺失或 Redis 出错，返回计费服务不可用。已尝试登记的所有维度按请求 ID 回滚，包括 Redis 已写入但回复丢失的情形。显式关闭预留、简易模式和普通估算请求的既有策略保留；关闭预留仍不提供并发额度保护。
- **SEC-012**：迁移 `284_gemini_cache_creation_intents.sql` 增加创建意图表。发出 POST 前先原子登记，同一用户（跨 Key）和账号各最多一条未完成意图。网络错误、超时、5xx、408/409 或不可用成功响应不换号重建；意图不会因断线、进程重启或 TTL 到期消失。已证明未发送或明确拒绝的请求可解除占用；已持久化资源且用量记录成功，或者清理成功且已知输入用量记录成功后可结束意图。创建后的落库失败、计费记录失败、清理失败、无法确定 token 数等情况保留意图待核对。
- **SEC-013**：Flova 两次余额一致，包括零差额，只记录 `final_settlement_unverified` 并转人工；成本保持未核销，继续占用账号和用户的未知成本额度。超支熔断、用户退款期限和冻结报价不变。删除了后台自动核销入口。

### Gemini 创建意图的人工处理

本轮没有新增用户侧解除占用接口，用户重试或更换 API Key 不会清除未知结果。运维在受控数据库维护流程中检查 `gemini_cache_creation_intents WHERE resolved_at IS NULL`，结合 `public_id`、`account_id`、`account_identity_version`、`upstream_model`、`ttl_seconds` 和创建时间核对。供应商资源的标记为 `displayName = s2a-<public_id>`；它只是查询线索，**不是**供应商幂等键。

确认原网关进程的 POST 已结束，并在创建时的供应商身份下查找资源。查不到、TTL 已到或一次余额稳定都不能证明没有创建或没有费用。取得最终结果后，核对本地缓存绑定及 `gcache:create:<public_id>` 用量：保留合法已入账资源，或确认孤儿资源已清理并核对最终费用。未知供应商费用不能伪造为零，也不能未经账务审核向用户补扣。

完成核对后，以该条 `public_id` 且 `resolved_at IS NULL` 为条件，在事务内填写 `resolved_at` 和 `resolution`；后者记录操作人、工单、供应商凭据及处理结论。保留原行作为审计证据，不删除记录，不批量按年龄释放，不在上游仍可能执行时解除占用。没有足够证据时继续保持占用并停用相关供应商账号。

### 发布与验证边界

先在隔离 PostgreSQL 验证迁移 284 及唯一索引的并发行为。切换前暂停 Gemini 创建并排空旧实例在途操作，核对历史未知创建；运行迁移后再切换全部实例，避免旧代码绕过意图登记。Flova 同样必须停止旧 worker，并复核历史自动核销记录。新迁移不会补建旧版本丢失的创建意图，也不会追溯修改既有账单。

本地回归使用模拟 HTTP 上游、内存 Redis 和 SQLite 验证路由拒绝、取消后的槽占用、预留故障回滚、创建意图唯一约束及 Flova 不自动核销。真实供应商行为、PostgreSQL 迁移及生产运行效果仍需按发布流程验证；本轮不执行迁移、部署或真实服务请求。
