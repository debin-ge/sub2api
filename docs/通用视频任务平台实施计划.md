## 0. 文档职责

视频平台文档分工：

| 文档 | 解决的问题 |
|---|---|
| `通用视频任务平台需求设计.md` | What / Why：业务能力、架构边界和关键决策 |
| `通用视频任务平台实现方案.md` | How：接口、数据、状态、事务和安全实现 |
| 本文 | Order / Gate：任务顺序、依赖、完成定义、验证、灰度与回滚 |

能力和安全边界以需求设计为准；技术接口和事务语义以实现方案为准。本文不重新定义价格公式、Provider 协议或状态机，只把它们拆成可独立合并、验证和上线的工作包。

实施必须遵守：

- 不建设 `AssetStore` 或 `video_assets`。
- 输入媒体仅进入加密短期 `SubmissionSpool`；输出媒体仅流式代理。
- OpenAI 首发只调度 API Key 账户；OAuth、SetupToken、Azure 排除。
- 可按策略暴露 Provider identity、上游 ID和任务级临时凭证；用户独享/BYOK 账户可显式允许返回专属凭证。
- 共享账户池的 API key、OAuth token、cookie 和其他长期凭证在任何策略下都不可披露。
- 用户任务访问按 `user_id` 隔离，API key 只做归因。
- 首版只支持标准余额；订阅分组在上游提交前拒绝。
- `submission_unknown` 不重试 Create、不换账号、不自动退款。
- Grok 首轮保持现状，通用化迁移作为后续独立阶段。

### 9.3 OpenAI 媒体规则

- 平台层将参考图、参考/源视频和其他二进制输入统一建模为带 role 的 `VideoInput`；role 是类型化字段，不通过文件名或 MIME 猜测业务语义。
- capability catalog 同时约束 operation、role、MIME、数量和大小；Provider 未声明支持的 role 必须在 hold 和上游调用前失败。
- OpenAI `input_reference` 只允许图片；参考视频不能伪装进入该字段。
- OpenAI 的视频二进制输入首版只映射到官方支持的 character clip 和 uploaded edit；extension 使用已有 completed video ID，不重新上传参考视频。
- multipart 图片 MIME 只允许 JPEG/PNG/WebP，且必须与目标 size 的规则一致。
- character 视频、edit 上传视频的格式和大小来自 capability catalog。
- extensions 只接受已有 completed video 引用，不接受 characters 或 image reference。
- 合法但当前 Provider 不支持的 binary role 在 hold 和上游调用前返回 `video_capability_unsupported`；结构非法或未注册的 role 返回稳定的请求校验错误。

- Create 一旦进入上游请求，不执行 account failover。

### 12.5 门禁

- content 测试期间监控文件系统，确认无输出落盘。
- 慢客户端和中途断开不会泄漏 goroutine、连接或下载 semaphore。
- 返回上游 ID不改变本地 ID授权模型。
- `dedicated_credentials` 必须同时通过策略和账户所有权校验；仅修改响应策略不能把共享账号变成独享账号。
- worker 重启或 Redis 丢失后，`delete_failed` 能由 DB sweep 恢复且不会重复结算。
- 下载失败、过期或未下载不触发退款。

1. 关闭 OpenAI Provider 新建能力。
